BEP-029: Conceitos Fundamentais de WebServices

Introdução aos WebServices e comunicação entre sistemas distribuídos

Arquitetura de WebServices

Como os sistemas se comunicam através de WebServices

Componentes da Arquitetura

Servidor (Provider)

Sistema que fornece o serviço, expondo APIs para acesso aos dados e funcionalidades.

  • Expõe endpoints (URLs)
  • Processa requisições
  • Retorna respostas

Cliente (Consumer)

Sistema que consome o serviço, fazendo requisições ao servidor.

  • Faz requisições HTTP
  • Processa respostas
  • Exibe dados ao usuário

Fluxo de Comunicação

1. Cliente faz requisição HTTP
   GET /api/usuarios/123 HTTP/1.1
   Host: servidor.exemplo.com

2. Servidor processa requisição
   - Valida autenticação
   - Busca dados no banco
   - Formata resposta

3. Servidor envia resposta
   HTTP/1.1 200 OK
   Content-Type: application/json
   {
     "id": 123,
     "nome": "João"
   }

4. Cliente processa resposta
   - Parse do JSON
   - Exibe dados
   - Atualiza interface

Arquitetura Cliente-Servidor

Modelo Cliente-Servidor

Em WebServices, seguimos o modelo cliente-servidor:

  • 📱 Cliente: Faz requisições (aplicativo, navegador, outro servidor)
  • 🖥️ Servidor: Processa requisições e retorna respostas
  • 🌐 Rede: HTTP/HTTPS como meio de comunicação
  • 📦 Dados: JSON, XML ou outros formatos

Tipos de Arquitetura

Monolítica

Um único servidor fornece todos os serviços. Simples, mas pode ter limitações de escala.

Microserviços

Múltiplos serviços independentes, cada um com sua própria API. Mais escalável e flexível.

Em Camadas

Serviços organizados em camadas (apresentação, negócio, dados). Boa organização.

Distribuída

Serviços distribuídos em diferentes servidores/locações. Alta disponibilidade.

Camadas de Segurança

  • 🔒 HTTPS: Criptografia na transmissão
  • 🔑 Autenticação: Verificação de identidade (tokens, API keys)
  • 🛡️ Autorização: Controle de acesso (permissões, roles)
  • 🚧 Rate Limiting: Limitação de requisições
  • 🔍 Validação: Validação de dados de entrada

Boas Práticas de Arquitetura

  • ✅ Separação de responsabilidades: Cada serviço tem uma função específica
  • ✅ Stateless: Serviços não mantêm estado entre requisições
  • ✅ Versionamento: APIs devem ser versionadas (/api/v1/, /api/v2/)
  • ✅ Documentação: APIs devem ser bem documentadas
  • ✅ Tratamento de erros: Respostas de erro padronizadas
  • ✅ Monitoramento: Logs e métricas para acompanhamento
