Formatos de Dados: JSON

Estrutura e uso do formato JSON em WebServices

O que é JSON?

JSON (JavaScript Object Notation) é um formato de dados leve e fácil de ler, amplamente usado em APIs REST modernas. É baseado em JavaScript, mas é independente de linguagem.

Características:

  • ✅ Leve: Menor que XML, mais rápido para transmitir
  • ✅ Legível: Fácil de ler e entender
  • ✅ Nativo em JavaScript: Suportado nativamente
  • ✅ Simples: Estrutura simples e direta

Estrutura Básica do JSON

{
  "id": 123,
  "nome": "João Silva",
  "email": "joao@exemplo.com",
  "idade": 30
}

Elementos:

  • Objeto: Delimitado por chaves { }
  • Propriedades: Pares chave-valor separados por vírgula
  • Valores: Podem ser strings, números, booleanos, arrays, objetos
  • Strings: Sempre entre aspas duplas

JSON com Estrutura Complexa

{
  "usuarios": [
    {
      "id": 1,
      "nome": "João Silva",
      "email": "joao@exemplo.com",
      "endereco": {
        "rua": "Rua das Flores, 123",
        "cidade": "Salvador",
        "estado": "BA"
      },
      "telefones": ["71999999999", "71333333333"]
    },
    {
      "id": 2,
      "nome": "Maria Santos",
      "email": "maria@exemplo.com"
    }
  ]
}

Recursos Demonstrados:

  • ✅ Arrays: Lista de elementos entre [ ]
  • ✅ Objetos aninhados: Objeto dentro de objeto
  • ✅ Múltiplos tipos: Strings, números, arrays, objetos

JSON em WebServices REST

// Requisição GET
GET /api/usuarios/123 HTTP/1.1
Host: exemplo.com
Accept: application/json

// Resposta
HTTP/1.1 200 OK
Content-Type: application/json

{
  "id": 123,
  "nome": "João Silva",
  "email": "joao@exemplo.com"
}

// Requisição POST
POST /api/usuarios HTTP/1.1
Content-Type: application/json

{
  "nome": "Maria Santos",
  "email": "maria@exemplo.com"
}

Em APIs REST, JSON é o formato mais comum para troca de dados. É usado tanto em requisições quanto em respostas.

Vantagens do JSON

Performance

Mais rápido para processar e transmitir que XML.

Leve

Menor tamanho de arquivo, economiza banda.

Nativo

Suportado nativamente em JavaScript e muitas linguagens.

Legível

Fácil de ler e entender.

Limitações do JSON

  • ⚠️ Sem comentários: Não suporta comentários no formato
  • ⚠️ Sem namespaces: Não tem suporte a namespaces como XML
  • ⚠️ Tipos limitados: Suporta apenas tipos básicos (string, number, boolean, null, array, object)
  • ⚠️ Sem validação: Não tem esquemas de validação nativos (mas pode usar JSON Schema)

JSON vs XML

JSON

  • ✅ Mais leve e rápido
  • ✅ Mais simples
  • ✅ Nativo em JavaScript
  • ✅ Ideal para APIs REST
  • ❌ Sem validação nativa

XML

  • ✅ Mais robusto
  • ✅ Suporta validação (XSD)
  • ✅ Suporta namespaces
  • ✅ Ideal para SOAP
  • ❌ Mais verboso

Quando Usar JSON?

  • ✅ APIs REST: Formato padrão para APIs REST modernas
  • ✅ Aplicativos web/mobile: Fácil integração com JavaScript
  • ✅ Microserviços: Formato leve e eficiente
  • ✅ Quando performance importa: Mais rápido que XML
  • ✅ Dados simples: Ideal para estruturas de dados simples
