BEP-011: Introdução a Banco de Dados Relacionais

Conceitos fundamentais de bancos de dados relacionais

Conceitos Básicos - Tabelas e Estruturas

Estrutura de uma Tabela

Uma tabela é como uma planilha, mas com regras mais rígidas:

Exemplo: Tabela de Clientes

ID Nome Email Telefone
1 João Silva joao@email.com (71) 99999-9999
2 Maria Santos maria@email.com (71) 88888-8888

Componentes de uma Tabela

  • Coluna (Campo): Cada tipo de informação (Nome, Email, etc.)
  • Linha (Registro): Cada pessoa/objeto (João, Maria, etc.)
  • Célula: Intersecção de linha e coluna
  • Esquema: Estrutura da tabela (nomes das colunas)

Tipos de Dados Comuns

Tipo Descrição Exemplo
INT Números inteiros 1, 25, 100
VARCHAR Texto variável "João Silva"
DATE Data 2025-01-03
BOOLEAN Verdadeiro/Falso TRUE, FALSE

Constraints essenciais

  • NOT NULL: impede valores ausentes.
  • UNIQUE: evita duplicidade (ex.: emails).
  • CHECK: valida regra (ex.: idade >= 0).
  • DEFAULT: valor padrão (ex.: created_at CURRENT_TIMESTAMP).

Exemplo de schema (SQL)

CREATE TABLE clientes (
    id INTEGER PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    email VARCHAR(120) UNIQUE,
    idade INT CHECK (idade >= 0)
);

CREATE TABLE pedidos (
    id INTEGER PRIMARY KEY,
    cliente_id INT NOT NULL,
    produto VARCHAR(100) NOT NULL,
    valor DECIMAL(10,2) CHECK (valor >= 0),
    data DATE DEFAULT CURRENT_DATE,
    FOREIGN KEY (cliente_id) REFERENCES clientes(id)
);

Regras Importantes

  • Consistência: Todas as linhas têm as mesmas colunas
  • Tipos: Cada coluna tem um tipo específico
  • Ordem: As colunas têm ordem fixa
  • Nomes: Colunas têm nomes únicos

Analogia com Planilha

Uma tabela de banco de dados é como uma planilha, mas:

  • ✅ Mais rígida: Não pode misturar tipos na mesma coluna
  • ✅ Mais segura: Validação automática dos dados
  • ✅ Mais eficiente: Busca e ordenação mais rápida
