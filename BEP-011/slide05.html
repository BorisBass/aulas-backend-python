BEP-011: Introdução a Banco de Dados Relacionais

Conceitos fundamentais de bancos de dados relacionais

Modelo Entidade-Relacionamento (ER)

O que é o Modelo ER?

O Modelo Entidade-Relacionamento é uma representação gráfica que mostra como as entidades (tabelas) se relacionam em um banco de dados.

Conceitos Fundamentais

  • Entidade: Objeto do mundo real (Cliente, Produto, Pedido)
  • Atributo: Característica da entidade (Nome, Preço, Data)
  • Relacionamento: Conexão entre entidades
  • Cardinalidade: Quantos registros se relacionam

Exemplo: Sistema de E-commerce

👤 CLIENTE
  • ID (PK)
  • Nome
  • Email
🛒 PEDIDO
  • ID (PK)
  • Cliente_ID (FK)
  • Data
📦 PRODUTO
  • ID (PK)
  • Nome
  • Preço

Tipos de Relacionamentos

  • 1:1 (Um para Um): Um cliente tem uma conta
  • 1:N (Um para Muitos): Um cliente faz vários pedidos
  • N:N (Muitos para Muitos): Um pedido tem vários produtos

Cardinalidades

Símbolo Significado Exemplo
1 Exatamente um Um cliente tem um CPF
0..1 Zero ou um Um cliente pode ter um endereço
1..* Um ou muitos Um cliente faz pelo menos um pedido
0..* Zero ou muitos Um cliente pode fazer vários pedidos

Do ER para o modelo relacional

  • Entidade → vira tabela.
  • Atributo → vira coluna (com tipo/constraints).
  • Relacionamento 1:N → FK na tabela do lado N.
  • Relacionamento N:N → tabela associativa com duas FKs.

Exemplo: N:N com tabela associativa

CREATE TABLE pedidos (
    id INTEGER PRIMARY KEY,
    cliente_id INT NOT NULL,
    data DATE DEFAULT CURRENT_DATE,
    FOREIGN KEY (cliente_id) REFERENCES clientes(id)
);

CREATE TABLE produtos (
    id INTEGER PRIMARY KEY,
    nome TEXT NOT NULL,
    preco DECIMAL(10,2) NOT NULL
);

CREATE TABLE pedido_itens (
    pedido_id INT NOT NULL,
    produto_id INT NOT NULL,
    quantidade INT DEFAULT 1,
    PRIMARY KEY (pedido_id, produto_id),
    FOREIGN KEY (pedido_id) REFERENCES pedidos(id) ON DELETE CASCADE,
    FOREIGN KEY (produto_id) REFERENCES produtos(id)
);

Vantagens do Modelo ER

  • ✅ Visualização: Fácil de entender
  • ✅ Comunicação: Cliente e desenvolvedor falam a mesma linguagem
  • ✅ Planejamento: Evita erros de design
  • ✅ Documentação: Registra a estrutura do sistema
