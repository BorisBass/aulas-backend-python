Cardinalidades no Modelo ER

O que é Cardinalidade?

A cardinalidade define quantas instâncias de uma entidade podem se relacionar com quantas instâncias de outra entidade.

Tipos de Cardinalidade

1:1 (Um para Um)

Cada instância de uma entidade se relaciona com apenas uma instância da outra entidade

1:N (Um para Muitos)

Uma instância de uma entidade se relaciona com várias instâncias da outra entidade

N:N (Muitos para Muitos)

Várias instâncias de uma entidade se relacionam com várias instâncias da outra entidade

Cardinalidade 1:1 (Um para Um)

PESSOA
POSSUI
CPF
1 ↔️ 1

Uma PESSOA possui apenas um CPF
Um CPF pertence apenas a uma PESSOA

Cardinalidade 1:N (Um para Muitos)

CLIENTE
FAZ
PEDIDO
1 → N

Um CLIENTE pode fazer vários PEDIDOS
Um PEDIDO pertence apenas a um CLIENTE

Cardinalidade N:N (Muitos para Muitos)

ALUNO
FREQUENTA
CURSO
N ↔️ N

Um ALUNO pode frequentar vários CURSOS
Um CURSO pode ter vários ALUNOS

Exemplos do Mundo Real

1:1 - Exemplos

  • Pessoa ↔ CPF
  • Funcionário ↔ Carteira de Trabalho
  • Carro ↔ Placa
  • Conta Bancária ↔ Cartão

1:N - Exemplos

  • Cliente → Pedidos
  • Departamento → Funcionários
  • Autor → Livros
  • Mãe → Filhos

N:N - Exemplos

  • Alunos ↔ Cursos
  • Médicos ↔ Pacientes
  • Livros ↔ Autores
  • Filmes ↔ Atores

Exemplo Prático: Sistema Escolar

ALUNO

João, Maria, Pedro

CURSO

Python, Java, SQL

N ↔️ N

João pode fazer Python e Java
Maria pode fazer Python e SQL
Pedro pode fazer Java e SQL

Importância das Cardinalidades

Design do Banco

Define como as tabelas serão criadas e relacionadas

Integridade

Garante a consistência dos dados

Consultas

Influencia como as consultas serão escritas

Performance

Afeta a performance das operações

Resumo das Cardinalidades

1:1

Relacionamento único entre duas entidades

1:N

Uma entidade se relaciona com várias da outra

N:N

Várias entidades se relacionam com várias da outra
