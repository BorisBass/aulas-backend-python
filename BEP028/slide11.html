Adicionando Persistência com SQLite

Evoluindo o sistema de tarefas: de memória para banco de dados

Por que Adicionar Persistência?

  • 📦 Dados Permanentes: Tarefas não são perdidas ao fechar o programa
  • 💾 Histórico: Podemos rastrear quando tarefas foram criadas
  • 🔄 Múltiplas Sessões: Dados persistem entre execuções
  • 📊 Escalabilidade: Preparado para crescer

Novo Componente: DatabaseManager

Classe para gerenciar conexão com SQLite (padrão BEP-017):

# database.py
class DatabaseManager:
    """Gerencia conexões com banco de dados"""
    
    def __init__(self, db_name='tarefas.db'):
        self.db_name = db_name
        self.connection = None
    
    def conectar(self):
        """Conecta e cria tabela se necessário"""
        if not self.connection:
            self.connection = sqlite3.connect(self.db_name)
            self._criar_tabela()
        return self.connection
    
    def _criar_tabela(self):
        """Cria tabela de tarefas"""
        cursor = self.connection.cursor()
        cursor.execute('''
            CREATE TABLE IF NOT EXISTS tarefas (
                id INTEGER PRIMARY KEY AUTOINCREMENT,
                titulo TEXT NOT NULL,
                descricao TEXT,
                concluida INTEGER DEFAULT 0,
                data_criacao DATE DEFAULT CURRENT_DATE
            )
        ''')
        self.connection.commit()
    
    def fechar(self):
        """Fecha conexão"""
        if self.connection:
            self.connection.close()

Mudanças no Model: Tarefa

❌ Antes (Memória) 
def __init__(self, titulo, descricao=""):
    self._titulo = titulo
    self._descricao = descricao
    self._concluida = False
✅ Depois (SQLite) 
def __init__(self, titulo, descricao="", 
                 tarefa_id=None, concluida=False, 
                 data_criacao=None):
    self._id = tarefa_id
    self._titulo = titulo
    self._descricao = descricao
    self._concluida = concluida
    self._data_criacao = data_criacao
💡 Por quê? O banco gera IDs automaticamente e precisamos armazená-los para atualizar/remover tarefas.

Mudanças no Repository

❌ Antes (Lista em Memória) 
def __init__(self):
    self._tarefas = []

def criar(self, tarefa):
    self._tarefas.append(tarefa)
    return len(self._tarefas) - 1

def listar_todas(self):
    return self._tarefas.copy()
✅ Depois (SQLite) 
def __init__(self, db_manager):
    self.db = db_manager
    self.db.conectar()

def criar(self, tarefa):
    cursor = self.db.get_cursor()
    cursor.execute('''
        INSERT INTO tarefas 
        (titulo, descricao, concluida)
        VALUES (?, ?, ?)
    ''', (tarefa.titulo, tarefa.descricao, 
          1 if tarefa.concluida else 0))
    self.db.connection.commit()
    return cursor.lastrowid

def listar_todas(self):
    cursor = self.db.get_cursor()
    cursor.execute('SELECT * FROM tarefas')
    # Converte resultados em objetos Tarefa
    return tarefas
💡 Novo Método: atualizar(tarefa) - necessário para salvar mudanças no banco!

Mudanças no Controller

Antes:

def __init__(self):
    self.repository = TarefaRepository()
    self.view = TarefaView()

def marcar_concluida(self):
    tarefa.marcar_concluida()  # Mudança em memória

Depois:

def __init__(self, repository, view):
    self.repository = repository  # Injeção de dependência
    self.view = view

def marcar_concluida(self):
    tarefa.marcar_concluida()
    self.repository.atualizar(tarefa)  # Salva no banco!
💡 Injeção de Dependência: Controller recebe dependências no construtor, facilitando testes e manutenção.

Mudanças no Main

# main.py
from database import DatabaseManager
from models import TarefaRepository
from views import TarefaView
from controllers import TarefaController

if __name__ == "__main__":
    # Inicialização explícita de componentes
    db_manager = DatabaseManager('tarefas.db')
    repository = TarefaRepository(db_manager)
    view = TarefaView()
    controller = TarefaController(repository, view)
    
    try:
        controller.iniciar()
    finally:
        db_manager.fechar()  # Garante fechamento

O que NÃO Mudou?

✅ View (views.py): Nenhuma mudança necessária!

Isso demonstra a flexibilidade do MVC - podemos mudar a persistência sem alterar a apresentação.
