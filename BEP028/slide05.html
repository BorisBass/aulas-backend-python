BEP-028: Introdução ao MVC

Model-View-Controller: Organizando código e separando responsabilidades

Separação de Responsabilidades

Como os componentes interagem e se comunicam

Diagrama de Interação MVC

📦 MODEL

Dados e Lógica de Negócio

🎮 CONTROLLER

Coordenação e Fluxo

🖥️ VIEW

Apresentação

Fluxo de Comunicação:

Usuário ↔ View ↔ Controller ↔ Model

Fluxo de Dados: Ação do Usuário

  1. Usuário interage com a View (ex: clica em botão)
  2. View envia ação para o Controller
  3. Controller processa a ação e valida entrada
  4. Controller chama métodos do Model
  5. Model executa lógica de negócio e atualiza dados
  6. Controller recebe resultado do Model
  7. Controller atualiza a View com novos dados
  8. View exibe resultado ao Usuário

Exemplo: Fluxo de Cadastro

# 1. Usuário escolhe opção no menu (View)
opcao = input("Escolha: ")  # View

# 2. Controller recebe e processa
if opcao == '1':
    controller.cadastrar_aluno()  # Controller

# 3. Controller pede dados à View
nome, idade, curso, nota = view.solicitar_dados_aluno()  # View → Controller

# 4. Controller cria Model (validação no Model)
aluno = Aluno(nome, idade, curso, nota)  # Controller → Model

# 5. Controller salva via Repository
repository.salvar(aluno)  # Controller → Repository → Banco

# 6. Controller pede View para exibir resultado
view.exibir_mensagem("Cadastrado!", "sucesso")  # Controller → View

# 7. View exibe ao usuário
print("✅ Cadastrado!")  # View → Usuário

Regras de Comunicação

✅ Comunicações Permitidas:

  • View → Controller (ações do usuário)
  • Controller → Model (operações)
  • Controller → View (atualizações)
  • Model → Controller (resultados)

❌ Comunicações Proibidas:

  • View → Model (direto)
  • Model → View (direto)
  • View acessa banco diretamente
  • Model chama View diretamente

Benefícios da Separação

  • ✅ Manutenção: Mudanças isoladas em cada componente
  • ✅ Testes: Testar cada parte independentemente
  • ✅ Reutilização: Mesmo Model com diferentes Views
  • ✅ Colaboração: Equipes trabalham em componentes diferentes
  • ✅ Escalabilidade: Fácil adicionar novas funcionalidades
