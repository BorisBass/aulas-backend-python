Model-View-Controller: Organizando código e separando responsabilidades

Componente Model

Responsabilidades e características do Model

O que é o Model?

O Model (Modelo) é responsável por:

  • 📦 Gerenciar dados: Armazenar e recuperar informações
  • 🔒 Lógica de negócio: Regras e validações do domínio
  • 💾 Persistência: Interação com banco de dados ou arquivos
  • ✅ Validação: Garantir integridade dos dados

Responsabilidades do Model

Deve Fazer:

  • Representar entidades do domínio
  • Validar dados antes de salvar
  • Interagir com banco de dados
  • Implementar regras de negócio
  • Fornecer métodos para acesso aos dados

NÃO Deve Fazer:

  • Exibir dados ao usuário
  • Processar entrada do usuário
  • Decidir qual View mostrar
  • Gerenciar navegação
  • Formatação de saída

Exemplo: Model de Aluno

# Model: models.py
class Aluno:
    """Model - Gerencia dados e lógica de negócio"""
    
    def __init__(self, nome, idade, curso, nota=None):
        self._nome = None
        self._idade = None
        self._curso = None
        self._nota = None
        
        # Validação (lógica de negócio)
        self.nome = nome
        self.idade = idade
        self.curso = curso
        if nota is not None:
            self.nota = nota
    
    @property
    def nome(self):
        return self._nome
    
    @nome.setter
    def nome(self, valor):
        if not valor or not valor.strip():
            raise ValueError("Nome é obrigatório")
        self._nome = valor.strip()
    
    @property
    def nota(self):
        return self._nota
    
    @nota.setter
    def nota(self, valor):
        if valor is not None and (valor < 0 or valor > 10):
            raise ValueError("Nota deve estar entre 0 e 10")
        self._nota = valor
    
    def __str__(self):
        return f"Aluno: {self.nome} - {self.curso}"
Características do Model:
  • ✅ Contém apenas lógica de negócio e dados
  • ✅ Não sabe nada sobre como os dados são exibidos
  • ✅ Pode ser reutilizado por diferentes Views
  • ✅ Fácil de testar isoladamente

Princípios do Model

  • ✅ Independência: Não depende de View ou Controller
  • ✅ Reutilização: Pode ser usado por múltiplas Views
  • ✅ Testabilidade: Fácil de testar sem interface
  • ✅ Encapsulamento: Protege dados e regras de negócio
  • ✅ Simplicidade: Foca apenas em dados e lógica de negócio
