Model-View-Controller: Organizando código e separando responsabilidades

Componente Controller

Responsabilidades e características do Controller

O que é o Controller?

O Controller (Controlador) é responsável por:

  • 🎮 Coordenação: Conectar Model e View
  • 📥 Entrada: Processar ações do usuário
  • 🔄 Fluxo: Decidir qual ação executar
  • 🔗 Comunicação: Mediar entre Model e View

Responsabilidades do Controller

Deve Fazer:

  • Receber entrada do usuário
  • Validar entrada básica
  • Chamar métodos do Model
  • Decidir qual View mostrar
  • Gerenciar fluxo da aplicação
  • Tratar erros e exceções

NÃO Deve Fazer:

  • Armazenar dados permanentemente
  • Exibir dados diretamente
  • Implementar regras de negócio complexas
  • Acessar banco diretamente
  • Formatação de saída

Exemplo: Controller de Aluno

# Controller: controller.py
from .models import Aluno
from .repository import AlunoRepository
from .view import AlunoView

class AlunoController:
    """Controller - Coordena Model e View"""
    
    def __init__(self, repository, view):
        self.repository = repository
        self.view = view
    
    def iniciar(self):
        """Inicia o sistema"""
        while True:
            self.view.exibir_menu()
            opcao = input("👉 Escolha uma opção: ").strip()
            
            if opcao == '1':
                self.cadastrar_aluno()
            elif opcao == '2':
                self.listar_alunos()
            elif opcao == '3':
                self.buscar_aluno()
            elif opcao == '0':
                self.view.exibir_mensagem("Até logo!", "sucesso")
                break
            else:
                self.view.exibir_mensagem("Opção inválida!", "erro")
    
    def cadastrar_aluno(self):
        """Processa cadastro de aluno"""
        try:
            # View coleta dados
            nome, idade, curso, nota = self.view.solicitar_dados_aluno()
            
            # Validação básica no Controller
            if not nome:
                self.view.exibir_mensagem("Nome é obrigatório!", "erro")
                return
            
            # Cria Model (validação de negócio no Model)
            aluno = Aluno(nome, int(idade) if idade else None, 
                        curso, float(nota) if nota else None)
            
            # Repository salva (persistência)
            self.repository.salvar(aluno)
            
            # View exibe resultado
            self.view.exibir_mensagem(f"Aluno '{nome}' cadastrado!", "sucesso")
        except ValueError as e:
            self.view.exibir_mensagem(str(e), "erro")
        except Exception as e:
            self.view.exibir_mensagem(f"Erro: {e}", "erro")
    
    def listar_alunos(self):
        """Lista todos os alunos"""
        alunos = self.repository.listar_todos()
        self.view.exibir_lista(alunos)
    
    def buscar_aluno(self):
        """Busca aluno por nome"""
        nome = input("Digite o nome: ").strip()
        alunos = self.repository.buscar_por_nome(nome)
        self.view.exibir_lista(alunos)
Fluxo do Controller:
  1. 📥 Recebe entrada do usuário (via View)
  2. ✅ Valida entrada básica
  3. 📦 Usa Model para criar/validar dados
  4. 💾 Usa Repository para persistir
  5. 🖥️ Usa View para exibir resultado

Controller como Intermediário

O Controller NUNCA comunica Model e View diretamente:

  • ❌ Errado: View acessa Model diretamente
  • ❌ Errado: Model chama View diretamente
  • ✅ Correto: Controller coordena tudo

Fluxo correto:

Usuário → View → Controller → Model → Repository → Banco

Banco → Repository → Model → Controller → View → Usuário

Princípios do Controller

  • ✅ Coordenação: Orquestra Model e View
  • ✅ Magreza: Deve ser "magro" (pouca lógica)
  • ✅ Delegação: Delega trabalho ao Model
  • ✅ Roteamento: Decide qual ação executar
  • ✅ Tratamento: Gerencia erros e exceções
