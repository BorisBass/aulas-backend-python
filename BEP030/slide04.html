BEP-030: RESTful Web Services e Métodos HTTP

Princípios REST e métodos HTTP para manipulação de recursos

Métodos HTTP: POST

Criar novos recursos

O que é POST?

O método POST é usado para criar novos recursos no servidor. É o método usado para enviar dados que resultarão em uma nova entidade.

Características:

  • ✅ Cria recursos: Adiciona novos dados ao servidor
  • ✅ Com corpo: Envia dados no corpo da requisição (JSON, XML, etc.)
  • ✅ Não idempotente: Múltiplas requisições criam múltiplos recursos
  • ✅ Modifica estado: Altera dados no servidor

Exemplo de Uso

// Criar um novo usuário
POST /api/usuarios HTTP/1.1
Host: exemplo.com
Content-Type: application/json

{
  "nome": "João Silva",
  "email": "joao@exemplo.com",
  "idade": 30
}

// Resposta (recurso criado)
HTTP/1.1 201 Created
Content-Type: application/json
Location: /api/usuarios/123

{
  "id": 123,
  "nome": "João Silva",
  "email": "joao@exemplo.com",
  "idade": 30,
  "criado_em": "2025-01-15T10:30:00Z"
}

Quando Usar POST?

Use POST para:

  • Criar novos recursos
  • Cadastrar usuários, produtos, etc.
  • Enviar dados de formulários
  • Operações que criam entidades

NÃO use POST para:

  • Buscar dados (use GET)
  • Atualizar recursos existentes (use PUT/PATCH)
  • Deletar recursos (use DELETE)

Validação em POST

POST geralmente requer validação dos dados enviados:

// Requisição com dados inválidos
POST /api/usuarios HTTP/1.1
Content-Type: application/json

{
  "nome": "",  // Nome vazio - inválido
  "email": "email-invalido"  // Email inválido
}

// Resposta de erro
HTTP/1.1 400 Bad Request
Content-Type: application/json

{
  "erro": "Dados inválidos",
  "detalhes": {
    "nome": "Nome é obrigatório",
    "email": "Email inválido"
  }
}

Status Codes para POST

  • ✅ 201 Created: Recurso criado com sucesso
  • ✅ 200 OK: Recurso criado e retornado (menos comum)
  • ⚠️ 400 Bad Request: Dados inválidos
  • ⚠️ 409 Conflict: Recurso já existe
  • ❌ 500 Internal Server Error: Erro no servidor
