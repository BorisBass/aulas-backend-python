Princípios REST e métodos HTTP para manipulação de recursos

Métodos HTTP: PUT e PATCH

Atualizar recursos

PUT vs PATCH

PUT

Substitui o recurso completo. Você deve enviar todos os campos, mesmo os que não mudaram.

  • ✅ Idempotente
  • ✅ Substitui recurso completo
  • ✅ Requer todos os campos

PATCH

Atualiza parcialmente o recurso. Você envia apenas os campos que deseja alterar.

  • ✅ Atualização parcial
  • ✅ Envia apenas campos alterados
  • ✅ Mais eficiente

Exemplo: PUT

// Atualizar usuário completo (PUT)
PUT /api/usuarios/123 HTTP/1.1
Content-Type: application/json

{
  "nome": "João Silva",
  "email": "joao.novo@exemplo.com",
  "idade": 31,
  "cidade": "Salvador"
}

// Resposta
HTTP/1.1 200 OK
Content-Type: application/json

{
  "id": 123,
  "nome": "João Silva",
  "email": "joao.novo@exemplo.com",
  "idade": 31,
  "cidade": "Salvador"
}

Exemplo: PATCH

// Atualizar apenas o email (PATCH)
PATCH /api/usuarios/123 HTTP/1.1
Content-Type: application/json

{
  "email": "joao.novo@exemplo.com"
}

// Resposta
HTTP/1.1 200 OK
Content-Type: application/json

{
  "id": 123,
  "nome": "João Silva",
  "email": "joao.novo@exemplo.com",
  "idade": 30,
  "cidade": "Salvador"
}

Quando Usar Cada Um?

Use PUT quando:

  • Quer substituir o recurso completo
  • Tem todos os dados do recurso
  • Precisa de operação idempotente

Use PATCH quando:

  • Quer atualizar apenas alguns campos
  • Quer economizar banda (menos dados)
  • Atualização parcial é suficiente

Boas Práticas

  • ✅ PATCH é mais comum: Na maioria dos casos, você só quer atualizar alguns campos
  • ✅ Validação: Valide os dados recebidos antes de atualizar
  • ✅ Status 404: Retorne 404 se o recurso não existir
  • ✅ Status 200 ou 204: Retorne 200 (com dados) ou 204 (sem dados) em sucesso
