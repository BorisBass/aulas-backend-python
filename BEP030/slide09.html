Princípios REST e métodos HTTP para manipulação de recursos

Modelagem de Recursos REST

Exercícios de modelagem de recursos

Exercício 1: Sistema de Biblioteca

Objetivo: Modelar recursos REST para um sistema de biblioteca.

Recursos:

  • Livros (título, autor, ISBN, ano)
  • Usuários (nome, email, telefone)
  • Empréstimos (livro, usuário, data_emprestimo, data_devolucao)

Tarefa: Crie as URLs RESTful para cada operação CRUD de cada recurso.

💡 Exemplo de Resposta:

// Livros
GET    /api/livros
POST   /api/livros
GET    /api/livros/123
PUT    /api/livros/123
DELETE /api/livros/123

// Usuários
GET    /api/usuarios
POST   /api/usuarios
GET    /api/usuarios/456
PATCH  /api/usuarios/456
DELETE /api/usuarios/456

// Empréstimos
GET    /api/emprestimos
POST   /api/emprestimos
GET    /api/emprestimos/789
PATCH  /api/emprestimos/789  // Para devolver livro

Exercício 2: E-commerce

Objetivo: Modelar recursos REST para um e-commerce.

Recursos:

  • Produtos (nome, preço, estoque, categoria)
  • Pedidos (cliente, produtos, total, status)
  • Itens do Pedido (pedido, produto, quantidade, preço)

Tarefa: Crie as URLs RESTful considerando relacionamentos entre recursos.

✅ Resposta sugerida:

// Produtos
GET    /api/produtos
POST   /api/produtos
GET    /api/produtos/10
PUT    /api/produtos/10
DELETE /api/produtos/10

// Pedidos
GET    /api/pedidos
POST   /api/pedidos
GET    /api/pedidos/500
PATCH  /api/pedidos/500   // atualizar status

// Itens do pedido (relacionamento)
GET    /api/pedidos/500/itens
POST   /api/pedidos/500/itens
PATCH  /api/pedidos/500/itens/3
DELETE /api/pedidos/500/itens/3

Exercício 3: Identificar Problemas

Objetivo: Identificar problemas nas URLs abaixo e corrigi-las.

// URLs com problemas
GET /api/getUser/123
POST /api/createProduct
PUT /api/updateOrder/456
DELETE /api/removeItem/789
GET /api/user/123/order

Tarefa: Reescreva as URLs seguindo os princípios REST.

✅ Resposta sugerida:

// Correções REST
GET    /api/usuarios/123
POST   /api/produtos
PUT    /api/pedidos/456
DELETE /api/itens/789
GET    /api/usuarios/123/pedidos

Dicas para Modelagem

  • ✅ Pense em recursos: O que são as "coisas" do seu sistema?
  • ✅ Use plural: Coleções sempre no plural
  • ✅ Hierarquia: Represente relacionamentos na URL
  • ✅ Consistência: Mantenha o mesmo padrão em toda API
  • ✅ Simplicidade: URLs devem ser intuitivas
