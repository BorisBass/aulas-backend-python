Princípios REST e métodos HTTP para manipulação de recursos

Métodos HTTP: DELETE

Remover recursos

O que é DELETE?

O método DELETE é usado para remover um recurso do servidor. É uma operação destrutiva que deve ser usada com cuidado.

Características:

  • ✅ Remove recursos: Deleta dados do servidor
  • ✅ Idempotente: Deletar o mesmo recurso múltiplas vezes tem o mesmo efeito
  • ✅ Sem corpo: Geralmente não envia dados no corpo
  • ⚠️ Irreversível: A operação geralmente não pode ser desfeita

Exemplo de Uso

// Deletar um usuário
DELETE /api/usuarios/123 HTTP/1.1
Host: exemplo.com

// Resposta (sucesso)
HTTP/1.1 204 No Content

// Ou com mensagem
HTTP/1.1 200 OK
Content-Type: application/json

{
  "mensagem": "Usuário deletado com sucesso"
}

// Resposta (recurso não encontrado)
HTTP/1.1 404 Not Found
Content-Type: application/json

{
  "erro": "Usuário não encontrado"
}

Segurança e Cuidados

Cuidados:

  • ⚠️ Operação irreversível
  • ⚠️ Requer autenticação
  • ⚠️ Pode afetar dados relacionados
  • ⚠️ Considere soft delete

Boas Práticas:

  • ✅ Verificar permissões
  • ✅ Confirmar antes de deletar
  • ✅ Usar soft delete quando possível
  • ✅ Retornar 404 se não existir

Status Codes para DELETE

  • ✅ 204 No Content: Recurso deletado com sucesso (sem corpo na resposta)
  • ✅ 200 OK: Recurso deletado com mensagem de confirmação
  • ⚠️ 404 Not Found: Recurso não existe
  • ⚠️ 403 Forbidden: Sem permissão para deletar
  • ❌ 500 Internal Server Error: Erro no servidor

Soft Delete vs Hard Delete

Soft Delete

Marca o recurso como deletado, mas mantém os dados no banco. Permite recuperação.

Hard Delete

Remove completamente os dados do banco. Não pode ser desfeito.
