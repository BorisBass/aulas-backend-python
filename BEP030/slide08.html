Princípios REST e métodos HTTP para manipulação de recursos

Estrutura de URLs RESTful

Como estruturar URLs em APIs REST

Princípios de URLs RESTful

  • ✅ Baseadas em recursos: URLs representam recursos, não ações
  • ✅ Nomes no plural: Use plural para coleções (/usuarios, /produtos)
  • ✅ Hierárquicas: Representam relacionamentos (/usuarios/123/pedidos)
  • ✅ Consistentes: Seguem um padrão previsível
  • ✅ Simples: Fáceis de entender e usar

Padrão de URLs RESTful

// Coleção de recursos
GET    /api/usuarios              → Lista todos os usuários
POST   /api/usuarios              → Cria um novo usuário

// Recurso específico
GET    /api/usuarios/123          → Busca usuário com ID 123
PUT    /api/usuarios/123          → Atualiza usuário 123
PATCH  /api/usuarios/123          → Atualiza parcialmente usuário 123
DELETE /api/usuarios/123          → Deleta usuário 123

// Sub-recursos (relacionamentos)
GET    /api/usuarios/123/pedidos  → Lista pedidos do usuário 123
POST   /api/usuarios/123/pedidos  → Cria pedido para usuário 123

Exemplos: Boas Práticas

✅ URLs RESTful (Corretas)

  • /api/usuarios - Coleção de usuários
  • /api/usuarios/123 - Usuário específico
  • /api/produtos - Coleção de produtos
  • /api/produtos/456 - Produto específico
  • /api/usuarios/123/pedidos - Pedidos do usuário

Exemplos: Evitar

❌ URLs Não-RESTful (Evitar)

  • /api/getUsuario?id=123 - Verbo na URL
  • /api/createUsuario - Ação na URL
  • /api/deleteUsuario/123 - Ação na URL
  • /api/usuario - Singular (deve ser plural)
  • /api/user/123 - Inglês inconsistente

Query Parameters

Use query parameters para filtros, paginação e busca:

// Filtros
GET /api/usuarios?idade=25
GET /api/usuarios?cidade=Salvador&idade=25

// Paginação
GET /api/usuarios?page=1&limit=10

// Busca
GET /api/usuarios?search=João

// Ordenação
GET /api/usuarios?sort=nome&order=asc

Versionamento de APIs

Inclua a versão da API na URL:

// Versão na URL
GET /api/v1/usuarios
GET /api/v2/usuarios

// Ou no header
GET /api/usuarios
Header: API-Version: 1.0

Recomendação: Use versão na URL para facilitar depreciação e evolução da API.
