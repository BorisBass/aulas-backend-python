BEP-030: RESTful Web Services e Métodos HTTP

Princípios REST e métodos HTTP para manipulação de recursos

O que é REST?

Conceitos fundamentais de REST

Definição de REST

REST (Representational State Transfer) é um estilo arquitetural para projetar sistemas distribuídos, especialmente aplicações web. Foi criado por Roy Fielding em 2000.

Em termos simples:

REST é uma forma de organizar APIs web de maneira padrão e intuitiva, usando os recursos e métodos HTTP de forma consistente.

Conceitos Fundamentais

Recursos (Resources)

Tudo que pode ser identificado por uma URL. Exemplos: usuários, produtos, pedidos.

Representações

Formato dos dados (JSON, XML, HTML). O mesmo recurso pode ter múltiplas representações.

Estado

Estado atual do recurso. Cada requisição transfere o estado atual.

Transferência

Comunicação entre cliente e servidor via HTTP.

Características do REST

  • ✅ Stateless: Cada requisição é independente, sem estado mantido no servidor
  • ✅ Baseado em recursos: URLs representam recursos, não ações
  • ✅ Usa métodos HTTP: GET, POST, PUT, DELETE para operações
  • ✅ Representações múltiplas: JSON, XML, HTML, etc.
  • ✅ Interface uniforme: Padrão consistente para todas as APIs

REST vs Não-REST (RPC/Ações)

Regra de bolso: REST usa substantivos (recursos) na URL e métodos HTTP para as ações. Não‑REST costuma usar verbos na URL e um único método para tudo.

REST

  • Recurso na URL: /usuarios, /produtos
  • Ação no método: GET, POST, PUT, DELETE
  • Stateless: cada requisição é independente
  • Resposta padronizada: status HTTP (200, 404, 500)

Não-REST

  • Verbo na URL: /getUsuario, /createUsuario
  • Método fixo: quase tudo via POST
  • Estado acoplado: fluxo depende de chamadas anteriores
  • Menos padronização: códigos e formatos variados

Exemplo: REST vs Não-REST

// ❌ Não-REST (RPC/Ações)
POST /getUsuario?id=123
POST /createUsuario
POST /updateUsuario
POST /deleteUsuario

// ✅ REST (Recursos + métodos HTTP)
GET    /usuarios/123      # Buscar usuário
POST   /usuarios          # Criar usuário
PUT    /usuarios/123      # Atualizar usuário
DELETE /usuarios/123      # Deletar usuário

Resumo: em REST a URL identifica o recurso; o método indica a ação.
