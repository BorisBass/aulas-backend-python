BEP-034: WebSockets e Comunicação em Tempo Real

Comunicação bidirecional em tempo real com WebSockets

HTTP vs WebSockets

Diferenças entre os protocolos de comunicação

HTTP - Request/Response

Características:

  • ✅ Unidirecional: Cliente faz requisição, servidor responde
  • ✅ Stateless: Cada requisição é independente
  • ✅ Fechado após resposta: Conexão é fechada
  • ⚠️ Cliente inicia: Servidor não pode enviar dados sem requisição
// Fluxo HTTP
Cliente → GET /api/mensagens → Servidor
Cliente ← 200 OK {mensagens} ← Servidor
[CONEXÃO FECHADA]

// Para novas mensagens, cliente precisa fazer nova requisição
Cliente → GET /api/mensagens → Servidor
Cliente ← 200 OK {mensagens} ← Servidor

WebSockets - Conexão Persistente

Características:

  • ✅ Bidirecional: Cliente e servidor podem enviar dados
  • ✅ Conexão persistente: Mantém conexão aberta
  • ✅ Tempo real: Dados chegam instantaneamente
  • ✅ Servidor pode iniciar: Servidor pode enviar sem requisição
// Fluxo WebSocket
Cliente → WS Connection → Servidor
[CONEXÃO ABERTA]

Servidor → Nova mensagem → Cliente
Cliente → Enviar mensagem → Servidor
Servidor → Mensagem recebida → Cliente
[CONEXÃO PERMANECE ABERTA]

Comparação

HTTP

  • Request/Response
  • Cliente sempre inicia
  • Conexão fechada após resposta
  • Stateless
  • Ideal para: APIs REST, páginas web

WebSocket

  • Bidirecional
  • Servidor pode iniciar
  • Conexão persistente
  • Stateful
  • Ideal para: Chat, notificações, jogos

Quando Usar Cada Um?

✅ Use HTTP quando:

  • APIs REST tradicionais
  • Requisições ocasionais
  • Dados que não mudam frequentemente
  • Operações CRUD

✅ Use WebSocket quando:

  • Comunicação em tempo real
  • Chat e mensagens
  • Notificações push
  • Atualizações frequentes
  • Jogos online

Handshake WebSocket

WebSocket começa como uma requisição HTTP e depois "upgrade" para WebSocket:

// 1. Cliente faz requisição HTTP especial
GET /ws/chat HTTP/1.1
Host: exemplo.com
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Key: dGhlIHNhbXBsZSBub25jZQ==

// 2. Servidor aceita e faz upgrade
HTTP/1.1 101 Switching Protocols
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Accept: s3pPLMBiTxaQ9kYGzzhZRbK+xOo=

// 3. Conexão WebSocket estabelecida
[AGORA É WEBSOCKET, NÃO MAIS HTTP]
