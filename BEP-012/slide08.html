Boas Práticas em SQL

Boas Práticas em SQL

Por que seguir boas práticas?

As boas práticas ajudam a escrever código SQL mais limpo, seguro e eficiente.

1. Nomes Descritivos

Use nomes claros e descritivos para tabelas e colunas.

-- ✅ Bom
CREATE TABLE clientes (
    id INTEGER PRIMARY KEY,
    nome_completo TEXT NOT NULL,
    email_contato TEXT
);

-- ❌ Evitar
CREATE TABLE c (
    i INTEGER PRIMARY KEY,
    n TEXT,
    e TEXT
);

2. Tratamento de NULL

NULL representa ausência de valor. Use IS NULL/IS NOT NULL para comparar.

-- ✅ Correto
SELECT * FROM clientes WHERE email IS NULL;
SELECT * FROM clientes WHERE email IS NOT NULL;

-- ❌ Incorreto
SELECT * FROM clientes WHERE email = NULL;

3. Aspas Simples

Use aspas simples para strings em SQL.

-- ✅ Correto
INSERT INTO clientes (nome, cidade) VALUES ('João Silva', 'Salvador');

-- ❌ Incorreto
INSERT INTO clientes (nome, cidade) VALUES ("João Silva", "Salvador");

4. SELECT Específico

Selecione apenas as colunas que você precisa.

-- ✅ Bom (mais rápido)
SELECT nome, email FROM clientes;

-- ❌ Evitar (mais lento)
SELECT * FROM clientes;

Resumo das Boas Práticas

  • Nomes claros: Use nomes descritivos para tabelas e colunas
  • NULL correto: Use IS NULL/IS NOT NULL para comparar
  • Aspas simples: Use ' ' para strings, não " "
  • SELECT específico: Selecione apenas colunas necessárias
  • Comentários: Use -- para explicar código complexo
