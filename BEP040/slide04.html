BEP-040: Autenticação e Autorização

Implementar sistemas de autenticação de usuários

Customização de Usuários

Estendendo o modelo User padrão do Django.

Por que customizar?

O modelo User padrão pode não ter todos os campos necessários. Você pode adicionar campos extras usando um modelo de perfil ou estendendo o User.

Método 1: Perfil (OneToOne)

# core/models.py
from django.contrib.auth.models import User
from django.db import models

class Perfil(models.Model):
    user = models.OneToOneField(User, on_delete=models.CASCADE)
    telefone = models.CharField(max_length=20, blank=True)
    data_nascimento = models.DateField(null=True, blank=True)
    bio = models.TextField(blank=True)
    foto = models.ImageField(upload_to='perfis/', blank=True)
    
    def __str__(self):
        return f"Perfil de {self.user.username}"

OneToOneField: Cada User tem exatamente um Perfil.

on_delete=models.CASCADE: Se User for deletado, Perfil também é deletado.

Vantagem: Não altera o modelo User padrão, fácil de implementar.

Usando o Perfil

# core/views.py
from django.contrib.auth.decorators import login_required
from .models import Perfil

@login_required
def meu_perfil(request):
    # Obter ou criar perfil
    perfil, criado = Perfil.objects.get_or_create(user=request.user)
    
    return render(request, 'perfil.html', {'perfil': perfil})

# No template
# {{ perfil.telefone }}
# {{ perfil.user.email }}

get_or_create(): Obtém o perfil se existir, ou cria um novo se não existir.

Use este método para evitar erros quando o perfil ainda não foi criado.

Método 2: Estender User (AUTH_USER_MODEL)

# core/models.py
from django.contrib.auth.models import AbstractUser
from django.db import models

class UsuarioCustomizado(AbstractUser):
    telefone = models.CharField(max_length=20, blank=True)
    data_nascimento = models.DateField(null=True, blank=True)
    bio = models.TextField(blank=True)
    
    class Meta:
        db_table = 'usuarios'
# meu_projeto/settings.py
AUTH_USER_MODEL = 'core.UsuarioCustomizado'  # usar modelo customizado

AbstractUser: Classe base que estende o User padrão.

AUTH_USER_MODEL: Define qual modelo usar para usuários.

Importante: Configure antes de criar migrations! Não pode mudar depois.

Qual método usar?

Perfil (OneToOne): Use quando já tem dados no banco ou quer manter compatibilidade.

UsuarioCustomizado: Use em projetos novos quando precisa de campos extras desde o início.

Recomendação: Para iniciantes, use Perfil (mais simples e seguro).
