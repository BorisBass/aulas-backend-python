BEP-033: Manipulação de Erros e Logs

Tratamento de erros e registro de logs em APIs

Tipos de Erros em WebServices

Erros comuns e como tratá-los

Categorias de Erros

4xx - Erros do Cliente

Erros causados pela requisição do cliente.

  • 400 Bad Request
  • 401 Unauthorized
  • 403 Forbidden
  • 404 Not Found
  • 409 Conflict

5xx - Erros do Servidor

Erros internos do servidor.

  • 500 Internal Server Error
  • 502 Bad Gateway
  • 503 Service Unavailable
  • 504 Gateway Timeout

Erros Comuns do Cliente (4xx)

400 Bad Request

Causa: Dados inválidos ou mal formatados

Exemplo: JSON malformado, campos obrigatórios faltando

401 Unauthorized

Causa: Não autenticado ou token inválido

Exemplo: Token expirado, credenciais inválidas

403 Forbidden

Causa: Autenticado mas sem permissão

Exemplo: Usuário comum tentando acessar área admin

404 Not Found

Causa: Recurso não encontrado

Exemplo: ID de produto que não existe

409 Conflict

Causa: Conflito com estado atual

Exemplo: Email já cadastrado, recurso em uso

Erros do Servidor (5xx)

500 Internal Server Error

Causa: Erro não tratado no servidor

Exemplo: Exceção não capturada, erro no banco

502 Bad Gateway

Causa: Servidor recebeu resposta inválida

Exemplo: Problema em serviço externo

503 Service Unavailable

Causa: Serviço temporariamente indisponível

Exemplo: Manutenção, sobrecarga

Exemplos de Respostas de Erro

// 400 Bad Request
HTTP/1.1 400 Bad Request
{
  "erro": "Dados inválidos",
  "detalhes": {
    "nome": "Nome é obrigatório",
    "email": "Email inválido"
  }
}

// 404 Not Found
HTTP/1.1 404 Not Found
{
  "erro": "Produto não encontrado",
  "detalhes": {
    "id": 123
  }
}

// 500 Internal Server Error
HTTP/1.1 500 Internal Server Error
{
  "erro": "Erro interno do servidor",
  "mensagem": "Ocorreu um erro ao processar sua requisição"
}

Boas Práticas

  • ✅ Mensagens claras: Erros devem ser compreensíveis
  • ✅ Detalhes úteis: Informe o que está errado e como corrigir
  • ✅ Status codes corretos: Use o código HTTP apropriado
  • ✅ Formato consistente: Mantenha estrutura de erro padronizada
  • ✅ Não exponha detalhes: Em produção, não mostre stack traces
