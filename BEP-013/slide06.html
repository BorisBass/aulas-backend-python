BEP-013: Comandos de Atualização e Remoção

UPDATE, DELETE e boas práticas para modificação de dados

Cuidados com UPDATE e DELETE

Por que ter cuidado?

Os comandos UPDATE e DELETE são irreversíveis na maioria dos casos. Uma operação mal executada pode resultar em perda permanente de dados importantes.

Principais Riscos

Sem WHERE

Altera/remove TODOS os registros

WHERE Incorreto

Altera/remove registros errados

Chaves Estrangeiras

Pode quebrar relacionamentos

Sem Backup

Dados perdidos para sempre

Regras de Ouro

-- REGRA 1: SEMPRE use WHERE
UPDATE clientes SET email = 'novo@email.com'
WHERE id = 1; -- ✅ CORRETO
-- ❌ PERIGOSO: UPDATE clientes SET email = 'novo@email.com';

Verificação Dupla

SEMPRE teste com SELECT antes de UPDATE/DELETE:

-- 1. Verificar quantos registros serão afetados
SELECT COUNT(*) FROM clientes
WHERE cidade = 'Salvador';
-- 2. Ver os registros específicos
SELECT id, nome, cidade FROM clientes
WHERE cidade = 'Salvador';
-- 3. Se estiver correto, executar UPDATE
UPDATE clientes
SET categoria = 'VIP'
WHERE cidade = 'Salvador';

Backup e Transações

Para operações críticas, use transações:

-- Iniciar transação
BEGIN;
-- Executar operação
UPDATE clientes SET status = 'inativo'
WHERE ultima_compra < '2020-01-01';
-- Se estiver tudo OK, confirmar
COMMIT;
-- Se houver problema, desfazer
ROLLBACK;

Cuidado com Chaves Estrangeiras

Ao deletar registros, verifique se não há dependências:

-- Verificar se cliente tem pedidos
SELECT COUNT(*) FROM pedidos
WHERE cliente_id = 5;
-- Se retornar 0, pode deletar o cliente
DELETE FROM clientes WHERE id = 5;

Dicas Importantes

  • Teste em ambiente de desenvolvimento antes de executar em produção
  • Faça backup antes de operações em massa
  • Use LIMIT em operações grandes para processar em lotes
  • Documente as operações importantes
  • Tenha um plano de rollback sempre
