Exceções genéricas vs customizadas

Versão 1: Exceções Genéricas

# Tratamento genérico
def cadastrar_aluno(cursor, conn):
    try:
        # ... código ...
        cursor.execute('''
            INSERT INTO alunos (nome, idade, curso, nota)
            VALUES (?, ?, ?, ?)
        ''', (nome, idade, curso, nota))
        conn.commit()
    except sqlite3.Error as e:
        print(f"❌ Erro no banco: {e}")
    except Exception as e:
        print(f"❌ Erro inesperado: {e}")

# Problema: mensagens genéricas, difícil identificar tipo de erro

Versão 2: Exceções Simplificadas

# Exceções customizadas básicas (BEP-022)
class ErroSistema(Exception):
    """Exceção base para erros do sistema"""
    pass

# Validação usa ValueError (padrão Python)
class Aluno:
    @nome.setter
    def nome(self, valor):
        if not valor or not valor.strip():
            raise ValueError("Nome é obrigatório")
        self.__nome = valor

# Uso: tratamento com ValueError
try:
    aluno = Aluno(nome="", nota=15.0)  # Dados inválidos
except ValueError as e:
    print(f"❌ {e}")  # Mensagem clara
except Exception as e:
    print(f"❌ Erro inesperado: {e}")

Vantagens do Tratamento de Exceções

  • ✅ Mensagens claras: ValueError com mensagens específicas
  • ✅ Tratamento adequado: Captura de ValueError para validação, Exception para erros gerais
  • ✅ Simplicidade: Uso de exceções padrão Python (BEP-022)
  • ✅ Manutenção: Fácil identificar e corrigir problemas
