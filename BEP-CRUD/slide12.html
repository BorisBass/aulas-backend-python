BEP-CRUD: Comparação entre Versões do Sistema CRUD

Procedural vs Orientado a Objetos

Conceitos Aplicados: BEP-017 a BEP-022

Conceitos de OO aplicados na Versão 2

Conceitos Utilizados

BEP-017: Fundamentos de POO

  • ✅ Classes: Aluno, DatabaseManager, AlunoRepository, etc.
  • ✅ Objetos: Instâncias das classes
  • ✅ Atributos e Métodos: Cada classe tem seus próprios

BEP-018: Criando e Instanciando Classes

  • ✅ Construtores: __init__ em todas as classes
  • ✅ Instanciação: aluno = Aluno(...)

BEP-019: Encapsulamento

  • ✅ Atributos privados: uso de _ e __ em atributos internos (convenção de encapsulamento)
  • ✅ Getters: @property para leitura de dados (forma “pythônica”)
  • ✅ Setters: @nome.setter, @nota.setter com validação de dados

BEP-020: Herança e Polimorfismo

  • ✅ Herança simples: exceção ErroSistema herda de Exception
  • ℹ️ Observação: nesta versão simplificada não usamos uma hierarquia grande de exceções nem polimorfismo avançado.

BEP-021: Composição e Associação

  • ✅ Composição: SistemaAlunos tem AlunoRepository e Menu
  • ✅ Associação: AlunoRepository usa DatabaseManager

BEP-022: Tratamento de Exceções

  • ✅ Try-except em classes: uso de try/except em métodos do sistema
  • ✅ Exceções simples: uso de ValueError, Exception e da exceção customizada ErroSistema

Conceitos que vão além das BEP-017 a BEP-022

  • ✨ @staticmethod (novo): usado na classe Menu para funções que não precisam de self, apenas para organizar a interface.
  • ✨ Pacotes e imports relativos (novos): uso de __init__.py e imports como from .models import Aluno para organizar o projeto como um pacote Python.
  • ✨ Metadados do módulo: nomes especiais como __version__, __author__ e __all__ em __init__.py, que ajudam na documentação/organização, mas não são obrigatórios.
  • ✨ Papéis das classes: Aluno (entidade), AlunoRepository (fala com o banco), DatabaseManager (gerencia conexão), Menu (interface de texto) e SistemaAlunos (orquestrador) — primeiros passos em direção a “padrões de projeto”.
  • ✨ Método especial __str__: usado em Aluno para imprimir o objeto de forma mais amigável.

Importante: esses recursos são apresentados aqui como bônus, para aproximar o código de projetos reais, mas vão além do mínimo exigido nas BEP-017 a BEP-022.

Convenções de Nomes Usadas no Código

  • 🧱 Classes: nomes em CamelCase (CapWords), como Aluno, DatabaseManager, AlunoRepository, SistemaAlunos — é uma convenção de estilo recomendada (PEP 8), não uma regra da linguagem.
  • 📄 Arquivos e módulos: nomes em minúsculas com underline, como models.py, database.py, repository.py.
  • 🔑 Atributos e métodos: em minúsculas com underline, como nome_completo, get_cursor().
  • 🔒 Encapsulamento por convenção: um underscore (_idade) indica “uso interno”, dois underscores (__nome) indicam atributo mais protegido; o Python aceita outros nomes, mas seguir essas convenções deixa o código mais claro para qualquer pessoa que leia.
