BEP-CRUD: Comparação entre Versões do Sistema CRUD

Procedural vs Orientado a Objetos

Comparação: Encapsulamento

Dados expostos vs dados protegidos

Versão 1: Sem Encapsulamento

# Dados em tupla - totalmente expostos
aluno = (1, "João", 20, "Python", 9.5, "2025-01-15")

# Qualquer um pode modificar diretamente
aluno = (1, "João", -5, "Python", 15.0, "2025-01-15")
# ❌ Idade negativa e nota > 10 - sem validação!

# Ou modificar índices incorretamente
aluno[1] = ""  # Nome vazio - sem validação!

# Não há proteção dos dados

Problema: Dados podem ser modificados incorretamente sem validação

Versão 2: Com Encapsulamento

# Dados em objeto - protegidos
aluno = Aluno(nome="João", idade=20, curso="Python", nota=9.5)

# Atributos privados (com _)
# aluno._nome  # Não deve ser acessado diretamente

# Acesso controlado via propriedades
aluno.nome = "Maria"  # ✅ Validação automática
aluno.nota = 15.0     # ❌ Erro! Nota > 10 (validação)

# Tentar acessar diretamente (não recomendado)
aluno._nota = 15.0    # ⚠️ Funciona, mas quebra encapsulamento

# Setter com validação
@nota.setter
def nota(self, valor):
    self._validar_nota(valor)  # Validação sempre!
    self._nota = valor

Vantagem: Dados protegidos, validação sempre aplicada

Conceito de Encapsulamento (BEP-019)

  • ✅ Atributos privados: _nome, _idade (convenção Python)
  • ✅ Getters: @property para leitura controlada
  • ✅ Setters: @nome.setter para escrita com validação
  • ✅ Proteção: Dados não podem ser modificados incorretamente
