Exemplo Prático: Singleton

Implementando o padrão Singleton em Python

O que é Singleton?

O padrão Singleton garante que uma classe tenha apenas uma instância e fornece um ponto global de acesso a ela.

Quando usar:
  • Conexões com banco de dados
  • Loggers (sistemas de log)
  • Configurações globais
  • Cache compartilhado

Antes do padrão: vários loggers independentes

Aqui temos o mesmo exemplo de Logger, mas sem usar o padrão Singleton.

class LoggerSimples:
    def __init__(self):
        self._logs = []
    
    def log(self, mensagem):
        self._logs.append(mensagem)
        print(f"[LOG] {mensagem}")
    
    def obter_logs(self):
        return self._logs.copy()

# Uso - CADA parte do sistema cria seu próprio logger
logger_a = LoggerSimples()
logger_a.log("Mensagem A")

logger_b = LoggerSimples()
logger_b.log("Mensagem B")

print(logger_a is logger_b)      # False - instâncias diferentes
print(logger_a.obter_logs())     # Só tem a mensagem A
print(logger_b.obter_logs())     # Só tem a mensagem B
Problema: cada parte do sistema tem uma lista de logs separada. Fica difícil ter uma visão única do que aconteceu no sistema.

Versão Simples: Singleton com @classmethod

✅ Esta versão é suficiente para começar! Usa apenas conceitos que você já conhece.

class Logger:
    _instancia = None
    
    def __init__(self):
        self._logs = []
    
    @classmethod
    def obter_instancia(cls):
        """Método que garante uma única instância"""
        if cls._instancia is None:
            cls._instancia = cls()  # Cria apenas na primeira vez
        return cls._instancia
    
    def log(self, mensagem):
        self._logs.append(mensagem)
        print(f"[LOG] {mensagem}")
    
    def obter_logs(self):
        return self._logs.copy()

# Uso - IMPORTANTE: sempre usar obter_instancia()
logger1 = Logger.obter_instancia()
logger1.log("Primeira mensagem")

logger2 = Logger.obter_instancia()  # Mesma instância!
logger2.log("Segunda mensagem")

print(logger1 is logger2)  # True
print(logger1.obter_logs())  # Ambas as mensagens
✅ Vantagens desta versão:
  • Usa apenas conceitos que você já conhece (@classmethod, __init__)
  • Fácil de entender e implementar
  • Funciona perfeitamente para garantir uma única instância

⚠️ Único detalhe: Precisa lembrar de usar Logger.obter_instancia() em vez de Logger() diretamente.

Versão Avançada: Singleton com __new__

📚 Conteúdo novo: Esta versão usa __new__, um método especial que você ainda não viu.

class Logger:
    _instancia = None
    
    def __new__(cls):
        """Controla a criação do objeto"""
        if cls._instancia is None:
            cls._instancia = super().__new__(cls)
        return cls._instancia
    
    def __init__(self):
        if not hasattr(self, 'inicializado'):
            self.inicializado = True
            self._logs = []
    
    def log(self, mensagem):
        self._logs.append(mensagem)
        print(f"[LOG] {mensagem}")
    
    def obter_logs(self):
        return self._logs.copy()

# Uso - Parece uma classe normal!
logger1 = Logger()  # Pode usar Logger() diretamente
logger1.log("Primeira mensagem")

logger2 = Logger()  # Mesma instância!
logger2.log("Segunda mensagem")

print(logger1 is logger2)  # True
print(logger1.obter_logs())  # Ambas as mensagens
✅ Vantagem desta versão: Parece uma classe normal (Logger()), mas por baixo dos panos garante uma única instância. Mais "transparente" para quem usa.

Por que introduzir __new__?

Importante: __new__ NÃO é obrigatório para implementar Singleton! A versão simples com @classmethod funciona perfeitamente.

Diferença entre __new__ e __init__:
  • __new__: Chamado ANTES - CRIA o objeto em memória
  • __init__: Chamado DEPOIS - INICIALIZA o objeto já criado

Por que mostrar __new__ então?

  • ✅ Transparência: Permite usar Logger() como uma classe normal
  • ✅ Conceito avançado: Mostra como Python cria objetos internamente
  • ✅ Curiosidade: Você verá esse padrão em código mais avançado

🎓 Para começar: Use a versão simples com @classmethod. É suficiente e mais fácil de entender!

Exemplo: Conexão com Banco de Dados

import sqlite3

class DatabaseConnection:
    _instancia = None
    _conexao = None
    
    def __new__(cls):
        if cls._instancia is None:
            cls._instancia = super().__new__(cls)
        return cls._instancia
    
    def conectar(self, database="app.db"):
        if self._conexao is None:
            self._conexao = sqlite3.connect(database)
            print("✅ Conexão estabelecida")
        return self._conexao
    
    def fechar(self):
        if self._conexao:
            self._conexao.close()
            self._conexao = None
            print("🔒 Conexão fechada")

# Uso - sempre a mesma conexão
db1 = DatabaseConnection()
db1.conectar()

db2 = DatabaseConnection()  # Mesma instância!
conn = db2.conectar()  # Reutiliza conexão existente

Cuidados com Singleton

⚠️ Problemas potenciais:
  • Dificulta testes unitários (dependência global)
  • Pode esconder dependências
  • Pode causar problemas em ambientes multi-thread
  • Pode ser um "code smell" se usado demais
✅ Use quando: Realmente precisa de uma única instância global (ex: configurações, conexões, loggers).
🎓 Resumo para começar:
  • ✅ Versão simples com @classmethod: Suficiente para a maioria dos casos
  • ✅ Versão com __new__: Mais "transparente", mas conteúdo avançado
  • ✅ Escolha: Comece com a versão simples, depois explore a avançada
