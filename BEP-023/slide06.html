BEP-024: Padrão Singleton

Garantindo uma única instância de uma classe

Padrão Singleton - Conceito e Teoria

Entendendo quando e por que usar Singleton

O que é Singleton?

O padrão Singleton garante que uma classe tenha apenas uma instância e fornece um ponto global de acesso a ela.

Definição formal: Singleton é um padrão criacional que restringe a instanciação de uma classe a um único objeto. Isso é útil quando exatamente um objeto é necessário para coordenar ações em todo o sistema.

Problema que Resolve

Às vezes, você precisa garantir que uma classe tenha apenas uma instância. Por exemplo:

❌ Sem Singleton:
  • Múltiplas conexões de banco de dados (desperdício de recursos)
  • Vários loggers escrevendo em arquivos diferentes (logs fragmentados)
  • Configurações globais duplicadas (inconsistência)
  • Cache compartilhado com múltiplas instâncias (dados duplicados)
✅ Com Singleton:
  • Uma única conexão de banco reutilizada
  • Um logger centralizado com todos os logs
  • Configurações globais consistentes
  • Cache único compartilhado por todo o sistema

Quando Usar Singleton?

✅ Use Singleton quando:

  • Precisa de exatamente uma instância de uma classe
  • Quer controlar acesso a recursos compartilhados
  • Precisa de um ponto global de acesso
  • Quer economizar recursos (ex: conexões de banco)
  • Precisa de estado global consistente

❌ Não use quando:

  • O problema não requer instância única
  • Precisa de múltiplas instâncias diferentes
  • Vai dificultar testes unitários
  • Adiciona complexidade desnecessária

Casos de Uso Comuns

Conexões de Banco de Dados

Garantir que apenas uma conexão seja criada e reutilizada, economizando recursos.

Sistemas de Log

Um logger centralizado que escreve todos os logs em um único arquivo ou stream.

Configurações Globais

Configurações do sistema que devem ser consistentes em toda a aplicação.

Cache Compartilhado

Um cache único que é compartilhado por toda a aplicação.

Vantagens e Desvantagens

✅ Vantagens:

  • Controle de acesso: Garante uma única instância
  • Economia de recursos: Evita criar múltiplas instâncias
  • Estado global: Permite estado compartilhado
  • Lazy initialization: Pode criar apenas quando necessário

⚠️ Desvantagens:

  • Testes: Dificulta testes unitários (dependência global)
  • Acoplamento: Pode criar acoplamento forte
  • Thread-safety: Requer cuidado em ambientes multi-thread
  • Anti-pattern: Pode ser usado como "global variable"

Princípio por Trás do Singleton

O Singleton funciona através de:

  1. Construtor privado: Impede criação direta de instâncias
  2. Método estático: Fornece acesso controlado à instância
  3. Variável de classe: Armazena a única instância criada
  4. Lazy initialization: Cria a instância apenas na primeira chamada
