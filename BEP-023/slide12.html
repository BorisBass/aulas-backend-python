Adicionando funcionalidades dinamicamente

Padrão Decorator - Conceito e Teoria

Entendendo quando e por que usar Decorator

O que é Decorator?

O padrão Decorator permite adicionar novos comportamentos a objetos dinamicamente, colocando-os dentro de objetos wrapper que contêm esses comportamentos.

Definição formal: Decorator é um padrão estrutural que permite anexar novos comportamentos a objetos, colocando-os dentro de objetos wrapper especiais que contêm esses comportamentos. O Decorator fornece uma alternativa flexível à herança para estender funcionalidades.

Problema que Resolve

Quando você precisa adicionar funcionalidades a objetos, mas não quer usar herança:

❌ Sem Decorator (usando herança):
  • Explosão de classes (Café, CaféComLeite, CaféComAçúcar, CaféComLeiteEAçúcar...)
  • Herança estática - não pode mudar em tempo de execução
  • Dificulta combinações de funcionalidades
  • Modificar classe base afeta todas as subclasses
  • Rígido e difícil de estender
✅ Com Decorator:
  • Composição dinâmica de funcionalidades
  • Pode adicionar/remover funcionalidades em tempo de execução
  • Fácil combinar múltiplas funcionalidades
  • Não modifica classe base
  • Flexível e extensível

Quando Usar Decorator?

✅ Use quando:

  • Precisa adicionar funcionalidades dinamicamente
  • Quer combinar múltiplas funcionalidades
  • Herança não é apropriada (explosão de classes)
  • Quer estender sem modificar classe base
  • Precisa de flexibilidade em tempo de execução

❌ Não use quando:

  • Funcionalidades são fixas e não mudam
  • Herança simples é suficiente
  • Adiciona complexidade desnecessária
  • Objetos são simples e não precisam de extensão

Casos de Uso Comuns

Bebidas e Adicionais

Café base + leite + açúcar + chantilly, combinando funcionalidades dinamicamente.

Streams de Dados

Adicionar compressão, criptografia, buffering a streams de forma combinável.

Autenticação e Autorização

Adicionar diferentes camadas de segurança (HTTPS, autenticação, autorização).

Formatação de Texto

Adicionar negrito + itálico + sublinhado a textos de forma combinável.

Decorator vs Herança

Herança

Estática, definida em tempo de compilação:

  • ✅ Mais simples para casos fixos
  • ✅ Melhor performance
  • ❌ Não pode mudar em runtime
  • ❌ Explosão de classes

Decorator

Dinâmica, definida em tempo de execução:

  • ✅ Flexível em runtime
  • ✅ Combina funcionalidades
  • ✅ Não modifica classe base
  • ❌ Mais complexo

Estrutura do Decorator

Componente: Interface comum que define operações básicas
Componente Concreto: Implementação básica do componente
Decorator: Classe abstrata que mantém referência ao componente
Decorator Concreto: Implementações específicas que adicionam funcionalidades
💡 Analogia: Como uma cebola - você pode adicionar camadas (decorators) ao redor do objeto base, cada camada adiciona uma funcionalidade.

Vantagens do Decorator

  • ✅ Flexibilidade: Adiciona funcionalidades dinamicamente
  • ✅ Composição: Combina múltiplas funcionalidades
  • ✅ Extensibilidade: Fácil adicionar novos decorators
  • ✅ Separação: Cada decorator tem responsabilidade única
  • ✅ Reutilização: Decorators podem ser reutilizados

Princípio por Trás do Decorator

O Decorator funciona através de:

  1. Composição: Decorator mantém referência ao objeto decorado
  2. Delegação: Decorator delega chamadas ao objeto decorado
  3. Envolvimento: Decorator "envolve" o objeto, adicionando comportamento
  4. Encadeamento: Múltiplos decorators podem ser encadeados
