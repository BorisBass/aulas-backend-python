BEP-023: Introdução aos Padrões de Projeto

Organizando código e promovendo reutilização através de padrões comprovados

Quando Usar Design Patterns?

Identificando oportunidades de aplicação

Sinais de que Precisa de um Padrão

✅ Use quando:

  • Você reconhece um problema comum
  • O código está duplicado ou desorganizado
  • Precisa desacoplar componentes
  • Quer facilitar manutenção futura
  • Precisa comunicar intenção claramente

❌ Não use quando:

  • O problema é simples demais
  • Adiciona complexidade desnecessária
  • Não há necessidade real
  • O código atual já está bom
  • Está apenas seguindo moda

Identificando Problemas Comuns

🔍 Problema: Múltiplas Instâncias

Sintoma: Criando vários objetos que deveriam ser únicos

Solução: Singleton

🔍 Problema: Criação Complexa

Sintoma: Muita lógica para criar objetos

Solução: Factory

🔍 Problema: Interfaces Incompatíveis

Sintoma: Sistemas que não se comunicam

Solução: Adapter

🔍 Problema: Notificações Múltiplas

Sintoma: Muitos objetos precisam ser avisados

Solução: Observer

Exemplo: Refatoração com Padrão

Antes: Código sem padrão (duplicado e difícil de manter)

# ❌ Sem padrão
def criar_notificacao_email(destinatario, mensagem):
    # código específico para email...
    pass

def criar_notificacao_sms(numero, mensagem):
    # código específico para SMS...
    pass

def criar_notificacao_push(token, mensagem):
    # código específico para push...
    pass

# Cada função em lugar diferente
# Difícil adicionar novos tipos
# Código duplicado

Depois: Com padrão Factory (organizado e extensível)

# ✅ Com Factory Pattern
class NotificacaoFactory:
    @staticmethod
    def criar(tipo, **kwargs):
        tipos = {
            "email": EmailNotificacao,
            "sms": SMSNotificacao,
            "push": PushNotificacao
        }
        classe = tipos.get(tipo)
        if classe:
            return classe(**kwargs)
        raise ValueError(f"Tipo {tipo} não suportado")

# Fácil adicionar novos tipos
# Código centralizado
# Fácil manutenção

Checklist: Devo Usar um Padrão?

  • ✅ O padrão resolve um problema real que você tem?
  • ✅ O código atual está difícil de manter ou estender?
  • ✅ O padrão simplifica o código?
  • ✅ Outros desenvolvedores vão entender facilmente?
  • ✅ O padrão melhora a qualidade do código?
Se respondeu "sim" para a maioria: Provavelmente é uma boa ideia usar o padrão!

Regra de Ouro

"Use padrões quando eles resolvem problemas reais, não porque são 'bonitos'."

✅ Boa Aplicação

Você tem um problema → Identifica padrão adequado → Implementa → Código melhora

❌ Má Aplicação

Você quer usar padrão → Procura problema → Força implementação → Código piora
