Anti-padrões: O que Evitar

Erros comuns ao usar padrões de projeto

O que são Anti-padrões?

Anti-padrões são soluções comuns a problemas recorrentes que são ineficazes ou contraproducentes. São padrões que parecem bons, mas na prática causam mais problemas.

⚠️ Atenção: Anti-padrões são tão importantes quanto padrões! Conhecê-los ajuda a evitar erros comuns.

Anti-padrão 1: God Object

Problema: Uma classe que faz tudo, violando o princípio de responsabilidade única.

# ❌ God Object - faz tudo
class Sistema:
    def processar_pedido(self): pass
    def enviar_email(self): pass
    def calcular_imposto(self): pass
    def gerar_relatorio(self): pass
    def conectar_banco(self): pass
    # ... 50 métodos mais
✅ Solução: Dividir em classes menores com responsabilidades específicas. Usar padrões como Facade para simplificar interface se necessário.

Anti-padrão 2: Singleton Excessivo

Problema: Usar Singleton para tudo, criando dependências globais difíceis de testar.

# ❌ Singleton em tudo
class Configuracao(Singleton): pass
class Logger(Singleton): pass
class Cache(Singleton): pass
class Database(Singleton): pass
class EmailService(Singleton): pass
# ... tudo é Singleton!
✅ Solução: Use Singleton apenas quando realmente precisa de uma única instância. Considere injeção de dependência para melhor testabilidade.

Anti-padrão 3: Over-Engineering

Problema: Aplicar padrões complexos para problemas simples.

# ❌ Over-engineering
# Criando AbstractFactory + Builder + Strategy
# para um sistema que apenas salva dados simples

class SimpleDataSaver:
    def save(self, data):
        # Solução simples seria suficiente
        with open("data.txt", "w") as f:
            f.write(data)
✅ Solução: Comece simples. Adicione padrões apenas quando necessário. "Premature optimization is the root of all evil."

Anti-padrão 4: Cargo Cult Programming

Problema: Copiar padrões sem entender por quê, apenas porque "é assim que se faz".

Exemplo: Usar Factory para criar apenas um tipo de objeto, ou usar Observer quando um simples callback seria suficiente.
✅ Solução: Entenda o problema antes de aplicar o padrão. Pergunte-se: "Este padrão realmente resolve meu problema?"

Outros Anti-padrões Comuns

  • ❌ Spaghetti Code: Código sem estrutura, difícil de seguir
  • ❌ Copy-Paste Programming: Duplicar código em vez de reutilizar
  • ❌ Golden Hammer: Usar sempre o mesmo padrão para tudo
  • ❌ Magic Numbers/Strings: Valores hardcoded sem explicação
  • ❌ Premature Abstraction: Criar abstrações antes de precisar

Como Evitar Anti-padrões

  • ✅ Entenda o problema antes de escolher solução
  • ✅ Comece simples, adicione complexidade quando necessário
  • ✅ Refatore quando identificar problemas
  • ✅ Code review ajuda a identificar anti-padrões
  • ✅ Aprenda com erros e experiências
