Padrão Factory Method - Conceito e Teoria

Entendendo quando e por que usar Factory Method

O que é Factory Method?

O padrão Factory Method fornece uma interface para criar objetos sem especificar suas classes exatas. A criação é delegada a subclasses ou métodos específicos.

Definição formal: Factory Method é um padrão criacional que define uma interface para criar objetos, mas permite que subclasses decidam qual classe instanciar. O Factory Method adia a instanciação para subclasses.

Problema que Resolve

Quando você precisa criar objetos, mas não sabe antecipadamente qual tipo exato será necessário:

❌ Sem Factory Method:
  • Código cliente conhece todas as classes concretas
  • Lógica de criação espalhada em vários lugares
  • Difícil adicionar novos tipos sem modificar código existente
  • Acoplamento forte entre cliente e classes concretas
  • Múltiplos if/elif para decidir qual objeto criar
✅ Com Factory Method:
  • Cliente não conhece classes concretas
  • Lógica de criação centralizada
  • Fácil adicionar novos tipos
  • Desacoplamento entre cliente e criação
  • Código mais limpo e organizado

Quando Usar Factory Method?

✅ Use quando:

  • Não sabe antecipadamente os tipos exatos de objetos
  • Quer desacoplar criação de uso
  • Precisa criar objetos relacionados
  • Quer centralizar lógica de criação
  • Precisa extensibilidade para novos tipos

❌ Não use quando:

  • Objetos são simples e diretos de criar
  • Não há variação nos tipos de objetos
  • Adiciona complexidade desnecessária
  • Criação é trivial e não muda

Casos de Uso Comuns

Sistemas de Notificação

Criar diferentes tipos de notificações (Email, SMS, Push) sem o cliente conhecer cada tipo.

Conexões de Banco

Criar conexões para diferentes bancos (SQLite, MySQL, PostgreSQL) de forma unificada.

Parsers de Arquivo

Criar parsers diferentes (JSON, XML, CSV) baseado no tipo de arquivo.

Formas Geométricas

Criar diferentes formas (Círculo, Retângulo, Triângulo) através de uma interface comum.

Factory Method vs Simple Factory

Simple Factory

Um método estático que cria objetos baseado em parâmetros:

  • ✅ Mais simples
  • ✅ Fácil de entender
  • ❌ Menos flexível
  • ❌ Não usa herança

Factory Method

Usa herança - subclasses implementam o método de criação:

  • ✅ Mais flexível
  • ✅ Usa polimorfismo
  • ✅ Extensível via herança
  • ❌ Mais complexo
💡 Para este curso: Começaremos com Simple Factory (mais simples) e depois veremos Factory Method completo (com herança).

Vantagens do Factory Method

  • ✅ Desacoplamento: Cliente não conhece classes concretas
  • ✅ Extensibilidade: Fácil adicionar novos tipos sem modificar código existente
  • ✅ Centralização: Lógica de criação em um só lugar
  • ✅ Manutenção: Mudanças na criação não afetam cliente
  • ✅ Testabilidade: Fácil criar mocks para testes

Princípio por Trás do Factory Method

O Factory Method funciona através de:

  1. Interface comum: Todos os objetos criados implementam a mesma interface
  2. Método de criação: Factory tem um método que decide qual objeto criar
  3. Encapsulamento: Lógica de criação fica escondida do cliente
  4. Polimorfismo: Cliente trabalha com a interface, não com implementações
