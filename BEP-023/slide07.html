Organizando código e promovendo reutilização através de padrões comprovados

Exemplo Prático: Factory

Implementando o padrão Factory em Python

O que é Factory?

O padrão Factory fornece uma interface para criar objetos sem especificar suas classes exatas. A criação é delegada a subclasses ou métodos específicos.

Quando usar:
  • Quando não sabe antecipadamente os tipos exatos de objetos
  • Quando quer desacoplar criação de uso
  • Quando precisa criar objetos relacionados
  • Quando quer centralizar lógica de criação

Implementação Básica

# Classes de produtos
class Carro:
    def acelerar(self):
        print("Carro acelerando...")

class Moto:
    def acelerar(self):
        print("Moto acelerando...")

# Factory
class VeiculoFactory:
    @staticmethod
    def criar(tipo):
        if tipo == "carro":
            return Carro()
        elif tipo == "moto":
            return Moto()
        else:
            raise ValueError(f"Tipo {tipo} não suportado")

# Uso
veiculo = VeiculoFactory.criar("carro")
veiculo.acelerar()

Exemplo Completo: Factory de Notificações

# Classes de notificação
class Notificacao:
    def enviar(self, mensagem):
        pass

class EmailNotificacao(Notificacao):
    def enviar(self, mensagem):
        print(f"📧 Email enviado: {mensagem}")

class SMSNotificacao(Notificacao):
    def enviar(self, mensagem):
        print(f"📱 SMS enviado: {mensagem}")

class PushNotificacao(Notificacao):
    def enviar(self, mensagem):
        print(f"🔔 Push enviado: {mensagem}")

# Factory
class NotificacaoFactory:
    @staticmethod
    def criar(tipo):
        tipos = {
            "email": EmailNotificacao,
            "sms": SMSNotificacao,
            "push": PushNotificacao
        }
        
        classe = tipos.get(tipo.lower())
        if classe:
            return classe()
        else:
            raise ValueError(f"Tipo de notificação '{tipo}' não suportado")

# Uso
notificacao = NotificacaoFactory.criar("email")
notificacao.enviar("Bem-vindo ao sistema!")

notificacao2 = NotificacaoFactory.criar("sms")
notificacao2.enviar("Seu código é 1234")
Vantagem: Código cliente não precisa saber como criar cada tipo. Fácil adicionar novos tipos sem modificar código existente.

Exemplo: Factory com Configuração

class DatabaseFactory:
    @staticmethod
    def criar_conexao(tipo, **kwargs):
        if tipo == "sqlite":
            return SQLiteConnection(kwargs.get("database"))
        elif tipo == "mysql":
            return MySQLConnection(
                host=kwargs.get("host"),
                user=kwargs.get("user"),
                password=kwargs.get("password")
            )
        elif tipo == "postgresql":
            return PostgreSQLConnection(
                host=kwargs.get("host"),
                user=kwargs.get("user"),
                password=kwargs.get("password")
            )
        else:
            raise ValueError(f"Tipo de banco '{tipo}' não suportado")

# Uso
db = DatabaseFactory.criar_conexao(
    "sqlite",
    database="app.db"
)

db2 = DatabaseFactory.criar_conexao(
    "mysql",
    host="localhost",
    user="admin",
    password="senha123"
)

Vantagens do Factory

  • ✅ Desacoplamento: Cliente não conhece classes concretas
  • ✅ Extensibilidade: Fácil adicionar novos tipos
  • ✅ Centralização: Lógica de criação em um só lugar
  • ✅ Manutenção: Mudanças na criação não afetam cliente
