BEP-038: URLs e Rotas no Django

Configurar rotas e URLs no Django

Reverse

Gerar URLs dinamicamente usando o nome da rota em vez de escrever a URL manualmente.

Por que usar reverse?

Vantagens:

  • Manutenibilidade: Se a URL mudar, só precisa alterar em um lugar
  • Segurança: Evita erros de digitação
  • Flexibilidade: Funciona mesmo com namespaces

reverse() em views

# core/views.py
from django.shortcuts import render, redirect
from django.urls import reverse
from .models import Tarefa

def criar(request):
    if request.method == 'POST':
        # ... cria tarefa ...
        return redirect(reverse('core:lista'))  # redireciona para lista
    return render(request, 'criar.html')

def detalhar(request, id):
    tarefa = Tarefa.objects.get(id=id)
    url_editar = reverse('core:editar', args=[id])  # gera /editar/1/
    return render(request, 'detalhar.html', {'tarefa': tarefa, 'url_editar': url_editar})

reverse('namespace:nome_rota'): Retorna a URL como string.

args=[valor]: Passa argumentos para URLs com parâmetros (ex: <int:id>).

{% url %} em templates


<!-- URL simples -->
<a href="{% url 'core:lista' %}">Ver Lista</a>

<!-- URL com parâmetro -->
<a href="{% url 'core:detalhar' tarefa.id %}">Ver Detalhes</a>

<!-- URL com múltiplos parâmetros -->
<a href="{% url 'produtos:categoria' categoria='livros' ano=2025 %}">Livros 2025</a>

{% url %}: Tag DTL que gera a URL automaticamente.

Se a rota mudar no urls.py, todos os templates são atualizados automaticamente.

Comparação prática: sem e com os conceitos

# SEM reverse / SEM namespace
# (funciona, mas URLs ficam "hardcoded")

# p1/urls.py
path('', include('core.urls')),
path('produtos/', include('produtos.urls')),

# core/views.py
def criar(request):
    if request.method == 'POST':
        # ...
        return redirect('/')  # URL fixa

# template.html
<a href="/detalhar/{{ tarefa.id }}/">Detalhar</a>
<a href="/produtos/categoria/livros/2025/">Livros 2025</a>
# COM reverse + namespace
# (recomendado: manutenção e organização)

# p1/urls.py
path('', include(('core.urls', 'core'), namespace='core')),
path('produtos/', include(('produtos.urls', 'produtos'), namespace='produtos')),

# produtos/urls.py
app_name = 'produtos'
urlpatterns = [
    path('categoria/<str:categoria>/<int:ano>/', categoria, name='categoria'),
]

# core/views.py
def criar(request):
    if request.method == 'POST':
        # ...
        return redirect(reverse('core:lista'))

# template.html
<a href="{% url 'core:detalhar' tarefa.id %}">Detalhar</a>
<a href="{% url 'produtos:categoria' categoria='livros' ano=2025 %}">Livros 2025</a>

Resumo: sem os conceitos, você depende de strings de URL espalhadas; com reverse e namespace, trabalha por nome de rota e evita conflitos entre apps.
